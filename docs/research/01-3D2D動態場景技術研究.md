# 3D／2D 動態場景網頁技術研究：工廠情境 × 影片輸出

- 日期：2026-11-01
- 目的：替「three.js + 開源模型的寫實工廠 3D 場景，可切換 2D，並能錄成影片／動畫」做技術盤點，作為後續規劃的依據
- 標記方式：✅ 已實測（npm registry 2026-11-01 查詢）｜📄 官方文件／README｜⚠️ 第二手來源，採用前要再核實

---

## 0. 結論先講

| 層 | 建議選型 | 理由 |
|---|---|---|
| 3D 引擎 | **three.js r187** + **React Three Fiber 9.8 / drei 10.7** | 生態最大、AI skill 最多、和 Remotion 能直接接 |
| 渲染器 | 先用 `WebGLRenderer`，架構預留 `three/webgpu` | WebGPU 在 r182 起成為建議渲染器，但 Linux／Intel Mac／Android 穩定支援還不完整 ⚠️；錄影走 headless Chrome 時，WebGL 比較穩 |
| 模型格式 | **glTF 2.0 (.glb)**，用 **gltf-transform** 最佳化（Meshopt + KTX2） | Khronos 標準格式，就是給執行期載入用的（runtime delivery） |
| 模型來源 | Kenney／Quaternius／Poly Haven／ambientCG（CC0）＋自建 | 授權乾淨，商用沒有疑慮 |
| 2D 切換 | **同一份「場景資料 JSON」產生兩種畫面**：① 同一個 3D 場景切換正交俯視相機 ② 另外輸出一份 SVG 平面圖 | 單一事實來源，2D／3D 的位置和狀態不會不同步 |
| 鏡頭編排 | 程式化的關鍵影格（GSAP 或自寫 timeline）；Theatre.js 當備選 | Theatre.js 最後一版是 2024-05，有停止維護的風險 ✅ |
| 影片輸出 | 三段式：**即時錄**（MediaRecorder）→ **逐格確定性錄**（WebCodecs + Mediabunny / canvas-record）→ **正式製作**（Remotion + `@remotion/three`） | 依照品質需求分層，前兩種免授權費 |

**最大風險**：
1. **Remotion 授權**：員工 4 人以上的公司要買 Company License，價格各來源說法不一致，要到官網確認。
2. **「寫實」的程度**：即時光柵化做不到真正的全域光照，要靠烘焙 lightmap、HDRI，或者用 path tracer 逐格離線渲染。
3. **現成工廠模型很少**：免費資源以低多邊形為主，寫實的機台多半要付費或自己建。

## 1. 3D 引擎比較

| 引擎 | 版本 ✅ | 授權 | 適合 | 備註 |
|---|---|---|---|---|
| **three.js** | 0.187.0 | MIT | 通用、客製程度最高 | r182 起 WebGPURenderer 為建議渲染器 ⚠️；TSL 著色語言可同時編譯成 GLSL 和 WGSL |
| **React Three Fiber** | 9.8.2 | MIT | React 宣告式場景 | 搭配 React 19；v8 對應 React 18，兩條版本線不要混用 |
| **drei** | 10.7.9 | MIT | R3F 輔助元件 | `useGLTF`、`Instances`、`Html` 標籤、`Environment`、`PerformanceMonitor`、`AdaptiveDpr` |
| Babylon.js | 9.33.1 | Apache-2.0 | 內建功能完整（物理、GUI、Inspector） | 是 three.js 的替代方案，但和 Remotion 整合比較麻煩 |
| PlayCanvas | 2.23.3 | MIT | 有線上編輯器，適合遊戲型場景 | |
| Needle Engine | 6.0.0-alpha | — | Unity／Blender 匯出到 three.js | 6.x 還是 alpha |

**WebGPU 現況** ⚠️：Chrome／Edge 113+、Safari 26+、Firefox 141+（Windows）／147+（Apple Silicon）都已支援；Linux、Intel Mac、Android 到 2026 年中還不穩定。
做法：`import * as THREE from 'three/webgpu'`，然後 `await renderer.init()`；建議鎖定 three 的版本，因為 TSL 的 API 還在變動。

### 1.1 寫實渲染技術清單

| 技術 | 用途 | 工具 |
|---|---|---|
| PBR 材質 | 金屬、粗糙度 | `MeshStandardMaterial` / `MeshPhysicalMaterial` |
| HDRI 環境光＋PMREM 預濾波 | 自然反射；沒做 PMREM 的話，反射會太銳利或有雜訊 | Poly Haven HDRI、drei `<Environment>` |
| 陰影 | 主光用 DirectionalLight＋補光用 Hemisphere | 大型廠房用 CSM（串接陰影貼圖） |
| 後處理 | SSAO、Bloom、色調映射、景深 | `@react-three/postprocessing` 3.2.2 ✅ |
| 烘焙光照 | 靜態廠房最省效能、也最寫實 | Blender 烘焙 lightmap 後匯出 glTF |
| 路徑追蹤 | 影片逐格渲染時可以拿到接近離線渲染器的品質 | `three-gpu-pathtracer` 0.0.27 ✅（即時互動太慢，適合錄影時逐格累積取樣） |
| 大量重複物件 | 料件、貨架、托盤 | `InstancedMesh` / drei `<Instances>` |
| 碰撞與點選加速 | 大場景 raycast | `three-mesh-bvh` 0.9.17 ✅ |
| 物理 | 料件掉落、輸送帶 | `@react-three/rapier` 2.2.0 ✅ |
| 機械手臂運動學 | 匯入 URDF、驅動關節角度 | `urdf-loader` 0.13.1 ✅（NASA JPL） |

## 2. 業界標準

### 2.1 3D 資產格式

| 標準 | 定位 | 本案用法 |
|---|---|---|
| **glTF 2.0 / GLB**（Khronos，ISO/IEC 12113） | 執行期交付格式，「3D 界的 JPEG」 | **主要格式** |
| KHR_draco_mesh_compression | 幾何壓縮，檔案最小，但解碼慢、解碼器大 | 只用在靜態大型網格 |
| EXT_meshopt_compression | 幾何壓縮，解碼快，也支援動畫 | **預設使用** |
| KHR_texture_basisu（KTX2） | GPU 壓縮貼圖，省顯示記憶體 | 手機版必用 |
| KHR_materials_* | 透射、clearcoat 等進階材質 | 玻璃、烤漆機殼 |
| KHR_mesh_quantization | 頂點量化 | 注意：Draco 本身已經會量化，不要重複套用 |
| **OpenUSD**（AOUSD／Linux 基金會） | 製作端的場景組合與交換格式，NVIDIA Omniverse 的基礎 | 如果日後要接 Omniverse／Isaac Sim，USD 是上游、glTF 是下游 |
| URDF | 機器人連桿與關節描述（ROS） | 機械手臂 |
| IFC | 建築 BIM | 廠房建築本體可以從 IFC 轉進來（That Open Engine） |

Khronos 工具 📄：**glTF Validator**、**glTF Asset Auditor**、**glTF Compressor**、Asset Creation Guidelines 2.0（SIGGRAPH 2025）。

最佳化指令（gltf-transform 4.5.1 ✅）：
```sh
npx @gltf-transform/cli optimize in.glb out.glb --compress meshopt --texture-compress ktx2 --texture-size 2048
npx @gltf-transform/cli inspect out.glb   # 看面數、貼圖大小、draw call
```

### 2.2 數位分身／工業資料標準（如果要接真實產線資料）

| 標準 | 內容 |
|---|---|
| **OPC UA**（IEC 62541） | 設備通訊與資訊模型；在數位分身文獻中被引用最多（文獻回顧：80 篇裡有 13 篇） |
| **Asset Administration Shell**（IEC 63278，IDTA） | 工業 4.0 的資產數位描述；OPC 30271 定義 AAS 和 OPC UA 之間的雙向映射（RC 2026-07） |
| **ISA-95**（IEC 62264） | 企業與控制層整合，定義工廠的階層模型（Enterprise→Site→Area→Line→Cell） |
| **ISO 23247** | 製造業數位分身框架 |
| MQTT / Sparkplug B | 常見的即時資料傳輸方式 |

> 建議：場景資料模型的階層直接採用 ISA-95（Site / Area / Line / Cell / Equipment），之後要接 MES 或 OPC UA 時不用改結構。

## 3. 2D 技術與 2D／3D 切換

### 3.1 2D 技術選型

| 技術 | 版本 ✅ | 適合 |
|---|---|---|
| **SVG + D3** | d3 7.9.0 | 平面圖、流程圖、資料綁定；可縮放、文字清楚、可以存成向量檔 |
| **GSAP** | 3.15.0（Standard no-charge license） | SVG／DOM／three.js 物件的時間軸動畫；MorphSVG、DrawSVG、MotionPath（料件沿路徑移動） |
| Motion | 14.9.0（MIT） | React UI 動畫 |
| PixiJS | 8.22.0 | 大量 2D 物件（數千個料件）時用 WebGL 2D |
| Konva | 10.9.1 | 可編輯的 2D 畫布（拖拉配置產線） |
| Lottie / dotLottie | lottie-web 5.13 / dotlottie-web 0.82 | 設計師用 AE 做的圖示動畫 |
| Rive | 2.49.0 | 有狀態機、可互動的向量動畫 |

### 3.2 切換架構（建議）

```
factory-layout.json （單一事實來源：ISA-95 階層 + 座標 + 設備型號 + 狀態）
        │
        ├─► 3D 模式：R3F 場景，透視相機
        ├─► 2D 模式 A：同一個場景切換 OrthographicCamera 俯視（只做相機轉場動畫，物件完全共用）
        └─► 2D 模式 B：同一份 JSON 產生 SVG 平面圖（線條圖風格、可輸出成 SVG／PDF）
```

- 模式 A：最省事、轉場最流暢（透視相機轉正交俯視可以做補間）；參考 That Open 的 `OrthoPerspectiveCamera`，以及社群 gist 的「依可視高度換算正交視錐」寫法。
- 模式 B：工程圖風格、文字最清楚，適合簡報和印刷；代價是要寫一份 2D 渲染器，好處是位置來自同一份 JSON，不會跑掉。
- 業界做法：論壇上的共識是「2D 用 Fabric／Paper／SVG，3D 用 three.js，資料共用」。

## 4. 動畫編排與影片輸出

### 4.1 鏡頭與時間軸

| 工具 | 版本 ✅ | 評估 |
|---|---|---|
| GSAP timeline | 3.15.0 | 用程式寫鏡頭路徑，可重現；**建議主力** |
| Theatre.js | core 0.7.2（**最後發布 2024-05**） | 有視覺化時間軸編輯器，可以匯出 state.json；但已經停更一段時間，風險偏高 |
| camera-controls | 3.1.2 | 平滑的相機轉場，例如 `setLookAt` 補間 |
| three.js `AnimationMixer` | 內建 | 播放 glTF 內建的動畫（手臂、輸送帶） |

### 4.2 錄影方案（三個層級）

| 層級 | 做法 | 品質 | 成本 |
|---|---|---|---|
| L1 即時錄 | `canvas.captureStream()` + `MediaRecorder` → WebM | 掉幀時影片也會跟著掉幀，每次錄的結果都不一樣 | 0 |
| L2 逐格確定性錄 | 暫停即時迴圈，每一格自己推進時間 t → 渲染 → `new VideoFrame(canvas, {timestamp})` → WebCodecs 編碼 → **Mediabunny**（1.65.0，MPL-2.0）封裝成 MP4；或直接用 **canvas-record** 6.0.0（MIT，支援 WebGL／WebGPU） | 幀率固定、畫質穩定，可以搭配 path tracer | 0 |
| L3 正式製作 | **Remotion 4.0.539** + `@remotion/three`（`<ThreeCanvas>`，用 `useCurrentFrame()` 驅動，**不能用 `useFrame`**）；可以用 headless Chrome（建議 ANGLE）批次算圖、加字幕、配樂、片頭片尾 | 最高，可程式化批次產出 | **員工 4 人以上要買 Company License** ⚠️ |
| 後製 | 本機 ffmpeg 9.0.2 ✅ 已安裝 | 轉檔、GIF、合併音軌 | 0 |

**關鍵設計原則**：所有動畫都寫成「時間 t 的純函數」，`scene.update(t)` 不讀 `clock.getDelta()`。這樣同一份程式碼可以同時給互動預覽、L2、L3 使用，不必重寫。

### 4.3 Remotion 授權 📄⚠️
- 免費：個人、員工 ≤3 人的營利組織、非營利組織。
- 其他情況：Company License，按用量計費。各來源寫的價格不一致（每次 render $0.01、每月最低 $100／$500、每席 $25 等），**要以 remotion.pro/license 為準**。
- 替代方案：L2（Mediabunny + 自寫 Puppeteer 逐格）可以完全避開授權費，代價是字幕、剪輯要自己做或交給 ffmpeg。

## 8. 待確認的決策（需要使用者決定）

1. **寫實程度**：即時互動等級（光柵化＋烘焙），還是影片電影等級（path tracer 逐格渲染）？兩者成本差很多。
2. **Remotion 授權**：公司規模是否超過 3 人？是否願意付 Company License？還是先走 L2 免費方案？
3. **2D 風格**：同一場景的正交俯視（A），還是工程平面圖 SVG（B），或兩者都要？
4. **是否接真實資料**（OPC UA／MQTT／MES）？會影響資料模型設計。
5. **成品發布位置**：是否放上 smarter.tw？如果是，要套用企業設計系統。
6. **模型預算**：只用 CC0，還是可以購買寫實機台？
